Bloco 1

Herança e relação “é um”

Reutilizar uma base quando existe uma relação de tipo verdadeira.

Problema

Classes relacionadas repetem estado e comportamento

Employee

nome, salário e pagamento

OutsourcedEmployee

nome, salário, pagamento e despesa adicional

A parte comum pode viver em uma superclasse; a parte específica permanece na subclasse.

Superclasse e subclasse

extends estabelece a relação

public class Employee {
    private String name;
    protected double basePayment;
}

public class OutsourcedEmployee extends Employee {
    private double additionalCharge;
}

Teste conceitual

A subclasse precisa ser utilizável como a superclasse

Gato é um Animal

boa relação

boa relação

Motor é um Carro

não é herança

Herança é transitiva, e Object está no topo das classes Java.

Um único objeto

A parte herdada e a parte específica não são objetos separados

Construtores não são herdados; membros privados não são acessados diretamente pela subclasse.

Membros herdados, acesso e super

Reutilizar a interface da base sem quebrar encapsulamento.

Encapsulamento

Campo privado continua pertencendo ao objeto, mas não é acessível diretamente

Superclasse

oferece métodos public ou protected

Subclasse

usa a API herdada para consultar ou alterar

Acesso protegido

protected combina pacote e herança

LocalAcesso
mesma classesim
mesmo pacotesim, mesmo sem herança
subclasse em outro pacotesim, pelas regras de herança e pelo receptor adequado
classe não relacionada em outro pacotenão

Parte herdada

super acessa a implementação da superclasse

@Override
public double payment() {
    return super.payment() + additionalCharge * 1.1;
}
super não é uma referência independente e não pode ser usado em contexto static.

Bloco 3

Construtores em hierarquias

A parte da superclasse é inicializada antes da subclasse.

Primeira etapa

Todo construtor chama outro construtor

public OutsourcedEmployee(String name, double base, double extra) {
    super(name, base);
    this.additionalCharge = extra;
}
Sem chamada explícita, o compilador tenta inserir super(). Se ele não existir ou não for acessível, o código não compila.

Invocação explícita

this(...) ou super(...): nunca os dois diretamente

this(...)

outro construtor da mesma classe

super(...)

construtor direto da superclasse

A cadeia sempre termina inicializando a superclasse antes do restante da subclasse.

Bloco 4

Sobrescrita de métodos

Uma subclasse fornece outra implementação do mesmo contrato.

Mesma assinatura

@Override permite ao compilador conferir a intenção

@Override
public double payment() {
    return super.payment() + additionalCharge * 1.1;
}
Se a assinatura estiver errada, a anotação transforma uma falha silenciosa em erro de compilação.

Contrato compatível

Regras centrais da sobrescrita

  • mesmo nome e mesmos parâmetros;
  • retorno igual ou covariante para referências;
  • acesso não pode ser mais restritivo;
  • método precisa ser herdável;
  • exceções verificadas obedecem regras estudadas depois.

Não confunda

Sobrescrita e sobrecarga resolvem problemas diferentes

Sobrescrita

mesma assinatura em subclasse; comportamento substituído

Sobrecarga

mesmo nome, parâmetros diferentes; escolha na compilação

06

Bloco 6

Polimorfismo e despacho dinâmico

A referência limita o acesso; o objeto escolhe a implementação.

Conversão para o tipo geral

Upcasting é implícito e seguro

Employee employee = new OutsourcedEmployee(
        "Ana", 1000.0, 200.0);

Tipo da referência: Employee.

Tipo real do objeto: OutsourcedEmployee.

Duas decisões

Compilador e JVM observam coisas diferentes

Compilador

verifica quais membros o tipo da referência permite chamar

Execução

seleciona a implementação sobrescrita pelo tipo real do objeto

Vários tipos concretos

Um array da superclasse recebe objetos de subclasses

Employee[] employees = {
    new Employee("A", 1000.0),
    new OutsourcedEmployee("B", 1000.0, 200.0)
};

for (Employee employee : employees) {
    System.out.println(employee.payment());
}

Limite do dinamismo

Sobrecarga é escolhida pelo tipo conhecido na compilação

Despacho dinâmico vale para métodos de instância sobrescritos. Ele não escolhe sobrecarga com base no tipo real do argumento.
07

Bloco 7

Downcasting e instanceof

Recuperar um tipo específico com verificação.

Conversão explícita

Downcasting compila, mas pode falhar em execução

Employee employee = new OutsourcedEmployee(...);
OutsourcedEmployee outsourced = (OutsourcedEmployee) employee;
Se o objeto não for realmente compatível, ocorre ClassCastException.

Verificar antes

Pattern matching testa e cria a variável já convertida

if (employee instanceof OutsourcedEmployee outsourced) {
    System.out.println(outsourced.getAdditionalCharge());
}
null instanceof Tipo produz false. A variável do pattern existe somente onde a condição garante o tipo.

Preferência de projeto

Polimorfismo reduz a necessidade de casting

Preferível

chamar comportamento declarado na superclasse e sobrescrito

Excepcional

converter quando uma operação realmente pertence apenas ao subtipo
