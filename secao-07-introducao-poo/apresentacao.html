Bloco 1

O problema sem orientação a objetos

A solução funciona, mas o modelo fica espalhado.

Dois triângulos

Seis variáveis para representar duas entidades

double xA, xB, xC;
double yA, yB, yC;

double p = (xA + xB + xC) / 2.0;
double areaX = Math.sqrt(p * (p-xA) * (p-xB) * (p-xC));

p = (yA + yB + yC) / 2.0;
double areaY = Math.sqrt(p * (p-yA) * (p-yB) * (p-yC));

O custo da repetição

Dados relacionados não estão agrupados

Nomes

As letras precisam indicar a qual triângulo cada lado pertence.

Cálculo

A mesma fórmula aparece mais de uma vez.

Evolução

Adicionar objetos aumenta variáveis e duplicação.

A POO começa como uma resposta de modelagem, não como uma nova fórmula.

Bloco 2

Classes, objetos e atributos

A classe define; cada objeto materializa um estado.

Molde

Uma classe declara os campos do modelo

public class Triangle {
    double a;
    double b;
    double c;
}
A declaração não cria automaticamente um triângulo. Ela define como objetos desse tipo serão estruturados.

Instâncias

new cria objetos distintos

Triangle x = new Triangle();
Triangle y = new Triangle();

Objeto x

a, b, c próprios

Objeto y

a, b, c próprios

A variável não contém o objeto inteiro

Operador ponto

A referência permite acessar os campos do objeto

Bloco 3

Métodos de instância

O comportamento passa a viver junto dos dados.

Responsabilidade

O triângulo conhece os lados usados em seu cálculo

public class Triangle {
    double a, b, c;

    double area() {
        double p = (a + b + c) / 2.0;
        return Math.sqrt(p * (p-a) * (p-b) * (p-c));
    }
}

Objeto receptor

Cada chamada usa o estado do objeto antes do ponto

x.area()

usa x.a, x.b e x.c

y.area()

usa y.a, y.b e y.c

Origem do dado

Campo pertence ao objeto; parâmetro chega pela chamada

Campo

Representa o estado persistente da instância.

double price;
×

Parâmetro

É um valor local recebido pelo método.

void addProducts(int quantity)

Bloco 4

Referências, stack, heap e coleta de lixo

Um modelo conceitual para prever identidade e alcance.

Modelo conceitual

Variáveis locais e objetos ocupam papéis diferentes

Stack

chamadas de métodos, parâmetros e variáveis locais

↔

Heap

objetos criados e seus campos

O modelo ajuda a raciocinar; detalhes físicos de implementação da JVM podem variar.

Duas referências

Atribuir uma referência não copia o objeto

Product p1 = new Product();
p1.name = "TV";

Product p2 = p1;
p2.name = "Monitor";

System.out.println(p1.name); // Monitor
p1 e p2 apontam para o mesmo objeto.

Trocar o alvo

Reatribuir a variável não altera o objeto anterior

p1 → objeto A
→
p1 = new Product()
→
p1 → objeto B
O objeto A continua existindo enquanto alguma referência alcançável ainda apontar para ele.

Referência especial

null significa “não aponta para objeto”

Product product = null;
// product.name causa NullPointerException

Comparar com null é permitido.

Acessar campo ou método exige um objeto.

Coleta de lixo

Um objeto se torna elegível quando deixa de ser alcançável

  • Elegível não significa removido imediatamente.
  • Não há garantia do instante em que o coletor executará.
  • A JVM decide quando recuperar a memória.
  • System.gc() é apenas uma solicitação.

Passagem por valor

Com objetos, a cópia contém o valor da referência

static void renomear(Product p) {
    p.name = "Novo";       // altera o objeto compartilhado
    p = new Product();     // altera somente a cópia local
}
Java continua passando por valor. O valor copiado é uma referência ao mesmo objeto.
05

Bloco 5

Object e toString

Uma representação textual útil para cada objeto.

Representação herdada

Toda classe deriva de Object

Product product = new Product();
System.out.println(product);
Sem sobrescrita, a forma padrão costuma combinar nome da classe e um código hexadecimal pouco útil para o domínio.

Representação útil

Sobrescrever toString descreve o estado relevante

@Override
public String toString() {
    return name
            + ", $ " + String.format("%.2f", price)
            + ", " + quantity
            + " units, Total: $ "
            + String.format("%.2f", totalValue());
}

Conversão implícita

Imprimir ou concatenar chama a representação textual

System.out.println(product);

usa product.toString()

String texto = "Dados: " + product;

também solicita texto

toString observa o objeto; não deve alterar seu estado.

Bloco 6

Estoque de produtos

Estado e comportamento reunidos em uma classe.

Classe de domínio

O produto conhece seu estoque

public class Product {
    String name;
    double price;
    int quantity;

    double totalValueInStock() { return price * quantity; }
    void addProducts(int quantity) { this.quantity += quantity; }
    void removeProducts(int quantity) { this.quantity -= quantity; }
}
Aqui this apenas distingue o campo do parâmetro; seu estudo completo vem na Seção 8.

Programa principal

Entrada e saída ficam fora da regra do produto

Program

lê dados com Scanner

Product

mantém estado e calcula

Program

mostra o resultado

Limite atual

Campos ainda podem receber qualquer valor diretamente

product.quantity = -100;
A classe já agrupa dados e comportamento, mas ainda não protege suas regras. Encapsulamento vem na Seção 8.

Bloco 7

Membros estáticos e de instância

Estado de cada objeto versus estado compartilhado pela classe.

Instância

Cada objeto possui sua própria cópia dos campos de instância

Product A

name = "TV"
quantity = 2

Product B

name = "Phone"
quantity = 5

Método

totalValue() usa o receptor

static

Um membro estático pertence à classe

public class Product {
    static int createdCount;
    static final double TAX_RATE = 0.10;

    String name;
}

Product.createdCount é compartilhado.

product.name pertence à instância.

Contexto estático

Sem objeto receptor, não há campo de instância implícito

static void mostrar() {
    System.out.println(createdCount); // permitido
    // System.out.println(name);     // não compila
}
Um método static pode usar uma instância recebida ou criada explicitamente, mas não possui this.

Como decidir

Pergunte a quem o dado ou comportamento pertence

Instância

Varia de objeto para objeto ou depende do estado daquele objeto.

static

É compartilhado, constante da classe ou não depende de instância.

Bloco 8

Introdução à POO na OCP Java SE 25

Prever referências, estado, alcance e acesso estático.

Pontos de prova

O que precisa estar claro

  • campos recebem valores padrão;
  • variáveis locais precisam ser inicializadas;
  • new cria um objeto;
  • atribuição de referência não copia o objeto;
  • null não referencia objeto.
  • Java passa referências por valor;
  • elegibilidade não garante coleta imediata;
  • membro de instância depende de objeto;
  • contexto estático não possui this;
  • toString fornece representação textual.

Leitura de código

Identidade do objeto e identidade da variável são diferentes

Product a = new Product();
Product b = a;
a = new Product();

Primeiro objeto continua alcançável por b.

a passa a apontar para outro objeto.

Nenhum objeto foi copiado.
