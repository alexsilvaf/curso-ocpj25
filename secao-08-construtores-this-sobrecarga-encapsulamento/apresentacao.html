Construtores

Inicializar o objeto no momento da criação.

Sintaxe

Construtor tem o nome da classe e não declara retorno

public Product(String name, double price, int quantity) {
    this.name = name;
    this.price = price;
    this.quantity = quantity;
}
void Product(...) seria um método, não um construtor.

Criação

new escolhe um construtor compatível

Product product = new Product("TV", 900.0, 2);

Bloco 3

Sobrecarga e encadeamento

Mesmo nome, listas de parâmetros diferentes.

Sobrecarga

Tipo, quantidade ou ordem dos parâmetros precisa mudar

static int soma(int a, int b) { ... }
static double soma(double a, double b) { ... }
static int soma(int a, int b, int c) { ... }
Mudar apenas o retorno, o nome dos parâmetros ou o modificador de acesso não cria outra assinatura.

Escolha da chamada

Java procura a assinatura mais específica aplicável

Correspondência exata

preferida

Ampliação primitiva

pode ser usada

Ambiguidade

não compila

Construtores encadeados

this(...) reutiliza outro construtor da mesma classe

public Product(String name, double price) {
    this(name, price, 0);
}

public Product(String name, double price, int quantity) {
    this.name = name;
    this.price = price;
    this.quantity = quantity;
}
this(...) precisa ser a primeira instrução explícita do construtor, salvo regras do corpo flexível do Java 25.

Java 25

Corpo flexível permite validação antes da invocação explícita

public Product(String name) {
    if (name.isBlank()) throw new IllegalArgumentException();
    this(name, 0.0, 0);
}
O trecho anterior a this(...) não pode acessar a instância antes de ela estar devidamente inicializada.

Bloco 5

Encapsulamento, getters e setters

Controlar como o estado pode ser consultado e alterado.

Campos privados

A classe protege sua representação interna

private String name;
private double balance;
Código externo não altera o campo diretamente; precisa usar operações oferecidas pela classe.

Consulta e alteração

Getter expõe um valor; setter pode validar

public String getName() { return name; }

public void setName(String name) {
    if (name == null || name.isBlank()) {
        throw new IllegalArgumentException("Nome invalido");
    }
    this.name = name;
}
Encapsular é preservar invariantes, não apenas gerar métodos.

API intencional

Nem todo campo precisa de setter

Saldo

muda por depósito e saque

Número

pode ser imutável com final

Derivado

pode ter getter calculado, sem campo

Classes de topo

Uma classe de topo usa public ou acesso de pacote

public class Product { }
ou
class ProductHelper { }
private e protected não são permitidos em classes de topo.

Geração pela IDE

Código gerado ainda exige decisão de projeto

  • Escolha quais campos entram no construtor.
  • Não gere setters para campos que não devem mudar livremente.
  • Revise nomes, validações e visibilidade.
  • Ferramentas aceleram a escrita; não definem invariantes.

Prática integrada: conta bancária

Construtores, encapsulamento e operações de domínio.

Estado protegido

Uma conta nasce válida e controla o saldo

public class BankAccount {
    private final int number;
    private String holder;
    private double balance;
    private static final double WITHDRAW_FEE = 5.0;

    public BankAccount(int number, String holder) {
        this(number, holder, 0.0);
    }
}

Pontos de prova

O que precisa estar consolidado

  • construtor não declara retorno;
  • declarar construtor remove o padrão implícito;
  • this não existe em contexto estático;
  • sobrecarga muda a lista de parâmetros;
  • this(...) encadeia construtores.
  • ordem textual de inicializadores importa;
  • campos final recebem valor uma vez;
  • acesso de pacote não usa palavra-chave;
  • classe de topo não pode ser private;
  • Java 25 admite corpo flexível com restrições.
